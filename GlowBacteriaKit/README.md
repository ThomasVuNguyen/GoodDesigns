# Glow-in-the-Dark Bacteria Engineering Kit (protocol PDF as a web page)

A web edition of The ODIN's printed protocol for the GFP bacterial transformation kit. The reference is not a website but an 18-page PDF. The page reproduces it page for page: every shape, image and letter is taken from the PDF rather than redrawn, then made usable on the web with selectable text, working checkboxes, a notes field and live links.

- **Reference:** `Glow-in-the-Dark_Bacteria_Engineering_Kit.pdf` (18 pages, 378 × 522 pt, modified 2026-10-09; exported through iLovePDF)
- **Captured:** 2026-10-14 (America/New_York)
- **Run:** from the repository root, `python3 -m http.server 8862 --directory GlowBacteriaKit/dist`, then open `http://localhost:8862/`.
- **Rebuild from the PDF:** `python3 -I GlowBacteriaKit/tools/build.py path/to/kit.pdf` (needs PyMuPDF and Pillow).

## Verification

Every page was screenshotted in Chrome and pixel-diffed against the PDF rendered by MuPDF at the same scale:
- desktop: 1280 × 900 viewport, page 680 px wide, 2× pixels;
- mobile: 390 × 844 viewport, page 390 px wide, 3× pixels.

| | Desktop | Mobile |
| --- | --- | --- |
| Mean difference per pixel (0–255) | 0.2–1.2 | 0.3–1.6 |
| Pixels differing by more than 32 levels | 0.02–0.57% | 0.03–1.1% |
| Of those, pixels away from a shape or glyph edge | 0–12 per page | 0–32 per page |

Every remaining difference lies on an edge, where Chrome and MuPDF anti-alias the same vectors slightly differently. No region differs in content, position or colour.

Both viewports had 0 console errors, 0 broken images, no horizontal overflow and 0 requests to other hosts. Checkboxes, the notes field (both saved across reloads), text selection and all four links were exercised in Chrome. Safari/WebKit has not been tested.

## How it works

The PDF has no usable fonts. Its text is drawn as vector outlines, and its only font is a Type3 text layer with empty glyphs that exists for search. So nothing is retyped or restyled:

- **`dist/pages/pNN.svg`**: each page's own vectors and images, exported by MuPDF from a copy of the PDF with two changes:
  - The background grid is a tiled 18 px image that MuPDF unrolls into about 1,100 masks per page. It is replaced by one SVG pattern built from the PDF's own values: 13.5 pt cells, 0.75 pt lines on the right and bottom edges, and a horizontal gradient `#c629f1` → `#02d862` with stops at 22.6% and 79.3%, at 6% opacity.
  - The ODIN cube logo is about 13,500 tiny paths. It is embedded as a 12× raster rendered from the page itself, because the logo's blend modes need the real sheet behind it.
- **Text layer**: transparent SVG `<text>` over each page, one element per PDF line, with every character at the x position and baseline the PDF records. Selecting text highlights the PDF's own glyphs, and copy, find-in-page and screen readers get real text. Lines of 15 pt and larger are marked as headings. The hidden layer has a few glitches (dropped capitals in "Bacteria" and "Petri", split words, a doubled "DH"), corrected in `build.py` so copied text reads as printed.
- **Overlays**: HTML positioned in percentages over the exact rectangles the PDF draws:
  - 31 checkboxes on its 12 pt squares;
  - the notes textarea on the 15 pt ruled card, with text sitting on the rules;
  - links over both QR codes (decoded: the YouTube agar-plate video and the-odin.com), "the-odin.com" and the email address.

  Ticks and notes save to `localStorage` (key `glow-kit-protocol:v1`).
- **Home button**: fixed top-left, linking to the GoodDesigns gallery at `/` (with `target="_top"`, so it also works from inside the gallery's viewer). On narrow screens, where the pages fill the width, it hides while scrolling down and returns on scroll up. When served on its own from `dist/`, `/` is this page.
- **Layout**: pages sit on a light grey backdrop with a soft shadow and a gap between them (32 px on desktop, 12 px on phones), like a document viewer. They are 680 px wide on desktop and scale to the screen width on phones. Each page height is snapped to a whole pixel, so fractional heights don't add up and shift later pages.

## Files

- `dist/index.html`: generated by `tools/build.py` from `tools/template.html`. Local asset URLs carry a content hash (`?v=…`) so a redeploy never pairs new HTML with a cached old stylesheet.
- `dist/assets/styles.css`, `dist/assets/app.js`, `dist/assets/favicon.webp`.
- `dist/pages/`: 18 SVGs (12 MB, embedded images re-encoded as lossless WebP so the pixels stay identical), served gzip-compressed by Firebase. Pages after the first two load lazily.

## Known differences

- This is the PDF's own artwork, so on phones the page is shown scaled down (body text about 11 px) rather than reflowed.
- Ticked checkboxes and typed notes don't exist in print. Untouched, the pages are identical.
- Copied text follows the PDF's text layer, so headings set in capitals copy in their source case ("Step: 1").
